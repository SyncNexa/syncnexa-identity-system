# School Configuration Management

**Purpose:** Document how school API configurations are added, managed, and rotated in SyncNexa.

---

## Overview

School configurations contain sensitive credentials (API tokens, HMAC secrets). These are:

- **Never stored in the database**
- **Managed via external Vault** (GCP Secret Manager)
- **Added through Admin Dashboard** (with audit trail)

---

## Adding a New School Configuration

### Step 1: Admin Creates Config Entry

**Via Admin Dashboard:**

```
Dashboard → School Integration → Add New School
```

**Form Fields:**

- Institution Code: `FUTO_NG` (unique)
- Institution Name: `Federal University of Technology Owerri`
- API Endpoint: `https://student.futo.edu.ng/api/v1/syncnexa/verify/request`
- [ ] Is Active (checkbox)

**Action:** Create → Config saved to database (without secrets)

### Step 2: Request Credentials from School

Admin contacts school IT and requests credentials:

- **API Token** (for `Authorization: Bearer <token>`)
- **HMAC Secret** (for signing callbacks to SyncNexa)

These must be generated by the school and shared securely.

**Example email:**

```
Subject: SyncNexa Integration - API Credentials Required

Dear FUTO IT Team,

We are integrating SyncNexa student verification with your institution.

Please provide the following credentials for our API integration:

1. API Token
  - Used in Authorization header: Bearer <token>
  - Secure, random token

2. HMAC Secret
  - Used for signing callbacks from your system to ours
  - Secure, random 32+ character string

Please share these securely via your preferred channel.

Thank you,
SyncNexa Team
```

### Step 3: School Provides Credentials

School IT provides:

- **API Token:** `futo_token_abc123xyz...`
- **HMAC Secret:** `hmac_secret_def456uvw...`

Delivered securely (encrypted email, secure password manager share, etc.).

### Step 4: Secrets Stored in Vault

SyncNexa stores in Vault (NOT database):

**Vault Path:** `syncnexa/schools/FUTO_NG`

**Secret Contents:**

```json
{
  "api_token": "futo_token_abc123xyz...",
  "hmac_secret": "hmac_secret_def456uvw...",
  "created_at": "2026-02-01T10:00:00Z",
  "provided_by": "futo_it@futo.edu.ng",
  "school_name": "FUTO"
}
```

### Step 5: Admin Activates Config

Admin confirms in dashboard:

- [ ] Credentials received from school
- [ ] Credentials stored in Vault
- [ ] Ready to test

**Action:** Activate → `vault_secret_path` populated, `is_active = true`

## Retrieving Credentials at Runtime

When SyncNexa needs to call school API:

```typescript
// 1. Get config from DB
const config = await db.getSchoolConfig("FUTO_NG");

// 2. Retrieve secrets from Vault (cached)
const secret = await vault.getSecret(config.vault_secret_path);

// 3. Use for API call
const response = await fetch(config.api_endpoint, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${secret.api_token}`,
    "X-Request-Signature": hmacSign(body, secret.hmac_secret),
    "X-Request-Timestamp": new Date().toISOString(),
  },
  body: JSON.stringify(verificationRequest),
});
```

**Key points:**

- Secrets retrieved at runtime, never logged
- Credentials never exposed in responses
- Vault access is audited

## Secret Rotation

### Why Rotate?

- Compliance (every 90 days)
- Suspected compromise
- Personnel changes at school

### How to Rotate:

**Step 1: Generate New Credentials**

```
Dashboard → School Config → FUTO_NG → Rotate Secret
```

Sets `secret_rotation_status = 'pending_activation'`

**Step 2: School Updates Their End**

School IT:

1. Receives new credentials via secure link
2. Updates their system
3. Tests with old credentials (still active)
4. Confirms ready

**Step 3: Admin Activates New Secret**

```
Dashboard → Confirm Rotation → New secret becomes active
Old secret deactivated
```

Updates in Vault:

```json
// OLD (deactivated)
{
  "api_token": "old_token...",
  "status": "deactivated",
  "deactivated_at": "2026-02-15T14:00:00Z"
}

// NEW (active)
{
  "api_token": "new_token...",
  "status": "active",
  "activated_at": "2026-02-15T14:00:00Z"
}
```

Database updated:

```sql
UPDATE school_api_configs
SET
  last_secret_rotated_at = NOW(),
  secret_rotation_status = 'active'
WHERE institution_code = 'FUTO_NG';
```

- **Rotate** - Initiate credential rotation
- **Deactivate** - Disable school (reversible)
- **Audit Log** - View all access/changes

### Credential Display Policy

**NEVER show secrets in UI:**

```
API Token:       ••••••••••••••••••
HMAC Secret:     ••••••••••••••••••
Last Rotated:    2026-02-01 10:30 AM
Rotation Status: Active
```

**IF admin needs to view (only for troubleshooting):**

- Requires MFA
- Shows last 4 characters only: `...xyz123`
- Logs access: `Admin John viewed FUTO_NG credentials`
- Auto-hides after 10 seconds

## Vault Setup (Implementation Details)

### GCP Secret Manager

```typescript
import { SecretManagerServiceClient } from "@google-cloud/secret-manager";

const client = new SecretManagerServiceClient();

async function getSchoolCredentials(vaultPath: string) {
  try {
    // vaultPath can be either:
    // 1) projects/<project>/secrets/<secret>/versions/latest
    // 2) <secret> (resolved using GOOGLE_CLOUD_PROJECT)
    const secretName = vaultPath.startsWith("projects/")
      ? vaultPath
      : `projects/${process.env.GOOGLE_CLOUD_PROJECT}/secrets/${vaultPath}/versions/latest`;

    const [version] = await client.accessSecretVersion({ name: secretName });
    const payload = version?.payload?.data?.toString("utf8") || "";

    return JSON.parse(payload);
  } catch (error) {
    logger.error(`Failed to retrieve secret: ${vaultPath}`, error);
    throw new Error("Credential retrieval failed");
  }
}
```
